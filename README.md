# つづり

親が自分のペースで質問に答え、人生のお話を確認済みの原稿として本にするサイト。

## 進め方

1. お名前・生年・出生地・家族を登録。
2. 一問ずつお話。回答を受けた追加質問に答えるか、次へ進む。
3. 章の下書きをAIで作成。元の回答を見ながら修正し、事実と表現を確認。
4. 確認した原稿だけを本に採用してダウンロード。

入力した回答をそのまま本として表示しません。原稿作成後に元のお話や基本情報を変更すると、その章は確認し直すまで本から外れます。回答、追加質問、下書き、進めていた場所はブラウザ内に保存されます。以前の回答も引き継ぎます。別端末への同期、家族間共有、PDF、音声入力は未対応です。

## 開発

Node.js 24、外部npm依存なし。

```sh
npm run dev
npm test
npm run build
```

開発サーバーはポート3000（`PORT`で変更可）。`dist/`は静的サイトです。単体版は`dist/tsuzuri.html`、GitHub Pages版は`docs/index.html`。静的配信のみではAI APIは動きません。

## Vercelで公開・AIを接続

1. VercelでGitHubの`yutakehub/first.app`をImport。
2. リポジトリの`vercel.json`を使用（build: `npm run build`、output: `dist`）。
3. VercelのEnvironment Variablesに以下を設定し、DeployまたはRedeploy。
   - `MEMOIR_AI_KEY`: OpenAI APIキー。値はVercelの秘密情報として保存し、チャットやGitへ書かない。
   - `MEMOIR_ACCESS_CODE`: 家族にだけ伝える十分に長い合言葉。匿名利用の防止に必要。
   - `MEMOIR_AI_MODEL`: 任意。初期値`gpt-4.1-mini`。
4. サイトの「AI編集の設定」で、家族の合言葉だけを入力。

`/api/status`は設定の有無だけを返します。`/api/followup`と`/api/draft`は合言葉を確認し、サーバーからOpenAIへ接続します。AIキーはフロントエンドへ配信しません。合言葉はそのタブのsessionStorageへ保存し、サーバー側では12回/分の制限を置いています（インスタンスごとの簡易制限）。合言葉を共有された相手はAIを利用できるため、公開サービスとして運用する場合は認証や永続的な利用制限を別途整えてください。

AI処理時には基本情報と対象章のお話をOpenAIへ送信します。AIには、出来事・感情・会話・年代を創作せず、本人の一人称で文脈をつなぐよう指示します。指示だけで完全な事実性は保証できないため、本人による確認・修正が必要です。原稿は自動採用されません。サーバーは回答や生成した原稿を保存しません。

現在の環境にはAIキー・合言葉・Vercel認証がなく、実際のAI通信・本番デプロイは未検証です。10件のローカルテストおよびブラウザ操作で、保存・再開・追加質問・原稿の確認・編集・採用・ダウンロードを検証しています。AIの応答はテスト用データで検証し、実際の生成品質を検証したものではありません。

## 約5,000字の自分史を目指す取材

6章の本文目安は、幼少期900字、家族900字、青春900字、仕事1,000字、子育て900字、現在と家族への言葉400字（合計5,000字）。基本質問は各章6問・全36問です。以前の質問と回答の対応は維持しています。

各回答には、具体的な場面・人物・当時の気持ちを聞く追加質問を用意し、短い回答には最大2回まで続けて聞きます。本人はいつでも飛ばせます。原稿画面では、素材の文字数、章の目標、下書きの実文字数を表示します。本全体の文字数には、確認済み原稿の本文だけを含め、見出しや空白、未確認の下書きは含めません。

素材の長さが章の目標の35%に届かない場合、生成前に追加取材を案内します。この比率は素材量の目安であり、十分な内容があることを保証しません。それ以上の素材があっても、AIが具体性不足を判断した場合は本文を生成せず追加質問を返し、「足りないお話を追加する」から回答できます。約5,000字は目標であり、質問を埋めるだけで到達を保証しません。字数のための創作や重複による水増しは行わないよう指示しています。実際のAI生成品質と文字数は、キー接続後に本人の回答を使って確認が必要です。
